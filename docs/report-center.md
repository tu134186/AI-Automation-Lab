# 中文报告中心
不需要 API 账户或独立网站。进入 GitHub Actions 任务摘要即可查看中文报告，底部提供下载入口。
每次任务导出 report.json、report.md、report.html、tests.log 和本次 Commit 对应的完整源码 ZIP。
HTML 无脚本、无外部资源，支持手机及系统深色模式；需要从产物下载后打开，GitHub 不直接托管此 HTML。
状态来自 unittest 实际结果及源码基础检查。错误、断言失败、失败的 subTest、跳过、预期失败均分别记录；空报告和跳过不会宣称全部通过。
修改记录取自本次 git show；任务及 Commit 链接取自 GitHub 运行上下文。页面中的下载入口指向任务页，任务摘要末尾另有真实产物链接。
原 lab_report.py CLI 和 JSON/Markdown/HTML 格式保留兼容。
运行：python3 scripts/run_report.py。退出码 0 表示所有检查通过，1 表示失败、跳过或无测试。
本分支源码变化触发一次 Linux 检查，同分支新任务自动取消旧任务；无需 iOS 云编译。
本阶段不包含离开对话后的通用 AI 自动修复。

## 真实任务历史
每次报告额外采集本仓库最近 10 次运行（排除当前运行），展示分支、Commit、UTC 启动时间及真实结论。
最多展开最近 3 个失败任务的具体失败步骤，最多查询最近 5 个已完成任务的产物；只展示未过期产物。
查询失败、查询限额或没有有效产物均明确说明，不把缺少结果当成成功。
导出 history.json、history.md；HTML 自动追加任务历史，任务摘要也直接展示，不需要独立网站。
这是本次运行时的快照，不是实时监控，不自动重新运行历史任务或修改历史故障。
使用 Actions 自带只读令牌，无需 OpenAI API、额外账号或收费模型。

## 历史结果变化与统计
按 GitHub 返回的新到旧顺序，在当前 10 条快照内比较相同 workflow_id（缺失时使用工作流路径）、相同分支的已完成有效运行。
只比较 success、failure、timed_out、startup_failure。取消、跳过、中立、等待和未知状态不计入通过率，也不作为上次通过／失败结果。
恢复通过仅表示相同工作流的执行结论由失败变为成功，不宣称特定业务故障已修复。
无有效结果时成功率显示暂无有效结果，不伪造 0% 或 100%。
JSON 历史 schema 升为 2，新增 metrics 和 comparison 字段；其余原字段保留。
固定入口见 README；不部署独立网页，也不创建定时任务。

## 待处理清单与诊断导出
在最近 10 条历史快照内，按工作流、分支分别寻找最近有效结果；最新有效结果已通过时，不把更旧的失败列为待处理。
更新任务取消、跳过或尚在运行不能证明旧失败已恢复；保留旧失败证据并提示更新任务状态。
只有排队／进行中的组显示等待结果；GitHub 的 action_required 单独显示需要操作。
每个失败 Job 提供依据数字 ID 构造的日志页面链接，不下载或复制原始日志。
排查方向仅依据失败步骤名，明确未确认根因；不会自动重试、付费调用或修改历史任务。
新增 diagnosis.md 和 diagnosis.json，与其他报告和源码一并打包。
清单为空只表示当前有限快照未发现待处理，不宣称仓库全部正常。history.json schema 升为 3，保留旧字段。
